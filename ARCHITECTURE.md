# Архитектура MultiplayerTest

## Общая схема

Проект использует авторитетную серверную модель Unreal Engine. Игрок, создавший лобби, запускает игровую карту как Listen Server. Второй игрок находит лобби через Steam и подключается по адресу, возвращённому Steam Online Subsystem. Изменения игрового состояния выполняются сервером, а клиентам передаются средствами репликации Unreal Engine.

```text
Главное меню
  -> MTSessionSubsystem
  -> Steam lobby / Steam Net Driver
  -> Listen Server
  -> MTCharacter
       -> MTInteractionComponent
       -> MTInventoryComponent
  -> MTChestActor
  -> MTItemPickup
  -> пользовательский интерфейс владельца
```

## Сессии и Steam

За жизненный цикл сессии отвечает `UMTSessionSubsystem`, созданный как `UGameInstanceSubsystem`. Он сохраняется при переходе между картами и предоставляет UI операции создания, поиска, подключения, выхода и уничтожения сессии.

При создании сессии:

1. Проверяется доступность Steam Net Driver.
2. Создаётся Steam-сессия максимум на двух игроков.
3. В настройках включаются presence и Steam lobbies.
4. Сессия получает метку проекта, чтобы не показывать посторонние лобби App ID `480`.
5. После успешного создания сервер открывает `/Game/Maps/L_Game` с параметром `listen`.

При подключении клиент получает результат поиска от Steam, вызывает `JoinSession`, запрашивает разрешённый адрес и выполняет `ClientTravel`. Адрес дополнительно проверяется: прямое IP-подключение для Steam-сессии отклоняется.

Состояние асинхронной операции описывается `EMTSessionOperation`. Изменения передаются интерфейсу событием `OnSessionOperationChanged`, ошибки публикуются через `OnSessionError`. Подсистема также обрабатывает сетевые ошибки, ошибки перехода между картами и тайм-ауты восстановления.

Связанные классы:

- `UMTMainMenuWidget` — создание лобби и отображение состояния операции.
- `UMTServerBrowserWidget` — запуск поиска и формирование списка результатов.
- `UMTServerRowWidget` — отображение отдельного лобби и запрос подключения.
- `FMTSessionInfo` — безопасная для UI копия данных результата поиска.
- `MTSessionFilter` — идентификация лобби этого проекта.

## Игрок и локальные системы

`AMTCharacter` содержит камеру от первого лица, `UMTInteractionComponent` и `UMTInventoryComponent`. Enhanced Input подключается только для локально управляемого персонажа. Локальными также остаются камера, UI и постпроцессная подсветка объекта под прицелом. Представление персонажа в мире реплицируется стандартными средствами `ACharacter`, поэтому участники видят перемещение друг друга.

`AMTPlayerController` управляет локальными виджетами: прицелом, главным меню и инвентарём. Виджеты не являются сетевым состоянием и не реплицируются.

## Взаимодействие

Интерактивные объекты реализуют `IMTInteractableInterface`. Интерфейс задаёт возможность взаимодействия, точку взаимодействия и само действие. Благодаря этому сундук и предмет используют один поток обработки.

`UMTInteractionComponent` определяет локальный объект в фокусе. При нажатии `E` клиент отправляет `ServerInteract` с выбранным актором. Сервер повторно проверяет существование и тип объекта, доступность взаимодействия, дистанцию и отсутствие препятствия. Только после успешной проверки вызывается реализация интерфейса. Подсветка и подсказка остаются локальными и не создают сетевого трафика.

## Сундук

`AMTChestActor` является реплицируемым актором. Флаг `bIsOpen` изменяется только сервером и реплицируется всем клиентам через `OnRep_IsOpen`.

Последовательность открытия:

1. Сервер убеждается, что сундук ещё закрыт.
2. Сервер создаёт `AMTItemPickup` в заданной точке.
3. Только после успешного появления предмета сундук помечается открытым.
4. `OnChestVisualStateChanged` обновляет визуальное состояние на сервере и клиентах.
5. Кратковременный эффект открытия запускается multicast-вызовом.

Повторное открытие исключается состояниями `bIsOpen` и `bIsOpening`.

## Предмет и подбор

`AMTItemPickup` реплицируется вместе с движением и ссылкой на `UMTItemData`. Data Asset содержит игровые и визуальные данные предмета: размер в сетке, иконку, меш и класс выброшенного предмета.

Подбор выполняется сервером:

1. Проверяется наличие места в инвентаре конкретного персонажа.
2. Предмет временно блокируется от конкурентного подбора.
3. `UMTInventoryComponent::TryAddItem` добавляет его в инвентарь взаимодействующего игрока.
4. После успеха сервер уничтожает `AMTItemPickup`.

Поскольку предмет является реплицируемым актором, его уничтожение отображается у всех участников. Если добавить предмет не удалось, блокировка снимается и предмет остаётся в мире.

## Инвентарь

`UMTInventoryComponent` хранит массив `FMTInventoryEntry`. Каждая запись содержит идентификатор экземпляра, ссылку на данные предмета и позицию в сетке 8 × 8. Размещение рассчитывается отдельным модулем `MTInventoryGrid`, который проверяет границы, пересечения, поиск свободного места и перемещение предметов разных размеров.

Сервер остаётся единственным источником истины для добавления, перемещения, удаления и выбрасывания предметов. Клиент может только отправить запрос `ServerMoveItem` или `ServerDropItem`.

Ключевое сетевое ограничение: Инвентарь реплицируется только владельцу

```cpp
DOREPLIFETIME_CONDITION(UMTInventoryComponent, Items, COND_OwnerOnly);
```

Массив `Items` передаётся только владельцу персонажа. Другой клиент не получает содержимое чужого инвентаря, при этом сервер хранит и проверяет состояние обоих игроков.

При выбрасывании сервер сначала создаёт и проверяет pickup перед персонажем и только затем удаляет запись из инвентаря. Это предотвращает потерю предмета, если создать его в мире невозможно.

## Пользовательский интерфейс

UI построен на UMG и разделён по ответственности:

- главное меню создаёт игру, показывает сетевой статус и открывает браузер серверов;
- браузер отображает публичные лобби этого проекта;
- строка сервера подключает игрока по индексу актуального результата поиска;
- инвентарь подписывается на `OnInventoryChanged` своего компонента и перестраивает локальное представление;
- виджет предмета отвечает за иконку и начало drag-and-drop;
- drag-and-drop operation переносит идентификатор предмета, а итоговую позицию подтверждает сервер.

Закрытие инвентаря возвращает игровой режим ввода. Кнопка выхода вызывает корректное уничтожение Steam-сессии и переход в главное меню.

## Репликация по объектам

| Объект или данные | Кто изменяет | Кому передаётся |
| --- | --- | --- |
| Положение персонажа | сервер | всем клиентам |
| `AMTChestActor::bIsOpen` | сервер | всем клиентам |
| `AMTItemPickup` и его уничтожение | сервер | всем клиентам |
| `AMTItemPickup::ItemData` | сервер | всем клиентам |
| `UMTInventoryComponent::Items` | сервер | только владельцу |
| меню, инвентарь и подсветка | локальный клиент | не реплицируются |

## Конфигурация

Steam включён в `Config/DefaultEngine.ini`. В качестве `GameNetDriver` используется Steam driver. Код подключения требует Steam-адрес и отклоняет прямой IP travel.

Карты `/Game/Maps/L_MainMenu` и `/Game/Maps/L_Game`, материалы подсветки и иконки включены в настройки упаковки в `Config/DefaultGame.ini`.

Основные зависимости модуля: `EnhancedInput`, `UMG`, `Slate`, `SlateCore`, `OnlineSubsystem`, `OnlineSubsystemUtils`, `OnlineSubsystemSteam` и `Niagara`.

## Проверяемые требования

| Требование | Реализация |
| --- | --- |
| Создание Steam-лобби | `UMTSessionSubsystem::CreateSession` |
| Поиск и подключение | `FindSessions`, `JoinSessionByIndex`, Steam connect string |
| Видимость игроков | репликация `ACharacter` в Listen Server |
| Общее состояние сундука | реплицируемый `bIsOpen` |
| Подбор конкретным игроком | серверное взаимодействие с его `UMTInventoryComponent` |
| Исчезновение предмета у всех | серверное уничтожение реплицируемого pickup |
| Отображение в своём UI | `OnInventoryChanged` и `UMTInventoryWidget` |
| Приватность инвентаря | `COND_OwnerOnly` для массива `Items` |
